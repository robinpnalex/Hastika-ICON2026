# Working on this repository together

Two people push to `task-b`. On 2026-10-05 that produced two different `24_*` and two
different `25_*` notebooks in `notebooks/task_b/`, and a notebook whose last cell
required an input that was not attached. These rules prevent both.

## Run numbers

- **Each task has its own sequence.** "Task A 20" and "Task B 20" are different runs.
- **Claim a number before creating the notebook.** Add a row to the roadmap table in
  `docs/EXPERIMENTS.md` with status `claimed`, then pull, commit and push it on its own.
  If the push is rejected, someone else claimed a number: pull and take the next one.
- **The filename starts with the number:** `notebooks/task_<x>/<NN>_<slug>.ipynb`, with
  exactly one file per number. The markdown title says `Task <X> Run <NN>`.
- **Output directory:** `/kaggle/working/<x><NN>_outputs`, for example `b28_outputs`, so
  two runs' outputs never collide.

## Notebooks must run standalone

- **Nothing may be required as an attached input.** An earlier run's output may be
  *reused* when attached: search with `os.walk("/kaggle/input", followlinks=True)`,
  because Kaggle's mount paths vary. When nothing is found, the notebook trains what it
  needs. Never `assert` that an input exists.
- **Clone the repo into `/tmp`, not `/kaggle/working`,** so the output holds only results.
- **Stop at 11 h.** Kaggle discards everything at 12 h.
  `hastika.common.gpu_queue.run_queue(..., stop_at=...)` does this.
- **The Gemma notebooks are generated by `experiments/build_gemma_notebooks.py`.** Edit
  the generator and rerun it rather than hand-editing those notebooks, or the next
  regeneration overwrites the edit.

## Shared code

- **`src/hastika/task_b/llm_classifier.py`, `llm_tapt.py` and `llm_screen.py` are shared
  by every Gemma notebook.** Add options with defaults that keep the old behaviour, and
  never change a default silently. Running notebooks clone the latest commit when they
  start.
- **Keep module paths stable.** Notebooks import them by name.
- **Before pushing:** `git pull --rebase origin task-b`, then
  `PYTHONPATH=src python -m unittest tests.test_structure`.

## Recording a run

1. Save the downloaded Kaggle log as `results/task_<x>/logs/run<NN>_<slug>.log`, and add
   a row to that folder's `README.md`.
2. Update the run's roadmap row in `docs/EXPERIMENTS.md` (status, result), and add a
   `### Run <NN> result` section with the per-arm table and the paired-bootstrap lines.
3. If the run changes the final recipe, update `docs/FINAL.md`.

## Where things live

| path | what |
|---|---|
| `docs/FINAL.md` | what goes into the final submission, and which runs decide it |
| `docs/EXPERIMENTS.md` | every run: roadmap table at the top, results below |
| `docs/IDEAS.md` | backlog and the graveyard of measured-and-dead ideas |
| `docs/task_<x>/NOTEBOOKS.md` | the index of notebooks, current line first |
| `data/derived/task_<x>_combined_holdout/` | the committed holdout splits; never regenerate them in place |
| `submissions/task_<x>/<name>/` | ZIPs that were, or will be, submitted |
